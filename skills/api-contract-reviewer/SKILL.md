# Api Contract Reviewer

This skill reviews an OpenAPI 3 document provided as a JSON file to identify common contract problems. Use this when you need to programmatically check an OpenAPI specification file for adherence to best practices.

## When to use

Use this skill when the user's request matches the description above and an input file is available. Do not use it for other kinds of input.

## Input

The OpenAPI 3 document content in JSON format.

Source languages named by the requirement: openapi-3. The skill itself does not depend on any of them.

## How to run

```
python3 scripts/api_contract_reviewer.py <path-to-input-file>
```

Requires Python 3.12 or newer, standard library only. The script reads one file (up to 5 MB), prints one JSON object to stdout, and exits 0 on success, 2 when the input is missing/unreadable/too large, 1 on an internal error. It performs no network access and writes no files.

## Output

A JSON object (schema: `schemas/output.schema.json`) with these fields:

| field | type | meaning |
|---|---|---|
| `issue_count` | integer | The total number of contract problems found in the document. |
| `issues` | array | A list of detected contract problems, each containing the rule, path, and message. |

## Steps

1. Attempt to parse the input JSON file to check for the `invalid-json` rule.
2. Check if the document contains a top-level `security` field; if not, and no operation defines its own security, report the `no-security` rule.
3. Iterate through all defined operations within the document to check for the `missing-operation-id` rule.
4. For every operation, check if it declares any 4xx, 5xx, or default response to report the `no-error-response` rule if none are present.
5. Construct the final JSON output containing the total count of reported issues and an array detailing each issue with its rule, path, and message.
